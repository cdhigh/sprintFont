## 文件格式坑（Sprint-Layout 文本设计格式固有）

- 2026-09-02: 旋转角单位在不同元素上不统一——焊盘 0.01°（sprint_pad.py）、TEXT 输出 0.001°，且解析时 TEXT/ID_TEXT 单位不同，还有 `>359 则 /10` 的修正补丁（sprint_textio_parser.py:283-287）。做角度相关改动时必须逐元素核对，不能假设统一单位。
- 2026-09-02: 输入文件编码回退链 latin-1 → utf-8 → locale 中 latin-1 永不抛 UnicodeDecodeError，utf-8/locale 分支实际是死代码；utf-8 文件中的非 ASCII 字符会变 mojibake（sprint_textio_parser.py:47-58）。[待确认] 是否要改成 utf-8 优先。
- 2026-09-02: Sprint 坐标原点左下 Y 向上，KiCad/SVG/freerouting 原点左上 Y 向下——所有格式转换都要 Y 取负（sprint_export_dsn.py、sprint_import_ses.py、svg_to_polygon.py、font_to_polygon.py 各自处理）。
- 2026-09-11: DXF 导出必须默认翻转 Y 轴 (mirrorY=True)——Sprint-Layout 屏幕视图中原点在左上且 Y 向下，AutoCAD DXF 遵循标准笛卡尔坐标系（原点左下、Y 向上），若不翻转会导致导出图元在 CAD/Viewer 中上下颠倒（sprint_to_dxf.py）。
- 2026-09-02: Sprint 文本绕左下角旋转，KiCad 文本绕中心对齐旋转，且 Sprint-Layout 无法计算文本实际宽度——导入封装后文本位置可能需要手工调整（README 注2），代码不做补偿。
- 2026-09-02: 角度正方向相反——KiCad 逆时针为正，Sprint 顺时针为正（kicad_definitions.py 头部注释）；freerouting 中 PTH 与 SMD 焊盘旋转方向也相反，DSN 导出统一用 `360-rotation`（sprint_export_dsn.py:302-304）。

- 2026-09-02: 立创封装坐标单位是 pixel(=10mil)，换算用 `mil2mm = 值/3.937`（lceda_to_sprint.py:63），不要按 px=25.4/96 处理。
- 2026-09-02: freerouting 的 DSN 兼容性 workaround（sprint_export_dsn.py）：image 里的 track 必须两两拆成独立 line，否则被当成封闭路径；`autoroute_settings` 段整块注释禁用——存在时 freerouting 经常报奇怪错误；等径钻孔视为开孔而非焊盘；单面焊盘在对面层加钻孔 keepout。

- 2026-09-19: SprintCircle 导出立创EDA必须按 start/stop 区分 CIRCLE 与 ARC（已修复）——之前 _writeCircle 忽略 start/stop 导致非整圆圆弧退化为整圆；立创 ARC 使用 SVG 路径格式 M startX startY A rx ry 0 largeArc 0 endX endY，因 Sprint 圆弧逆时针为正、在 Y 向下坐标系中对应 SVG sweep-flag 0；仅整圆、360°整数倍跨度或实心填充保留为 CIRCLE 图元（sprint_to_lceda.py）。
- 2026-09-19: OpenSCAD 导出在 mirrorY=True 下旋转角与圆弧必须镜像取反（已修复）——OpenSCAD 为笛卡尔 Y 向上且 rotate(θ) 逆时针为正，Sprint 内部焊盘旋转顺时针为正；垂直镜像 Y 后手性颠倒，焊盘旋转必须转为 (360 - θ) % 360，八角焊盘相应修正基准偏移 (rot + 22.5) % 360，圆弧起止角也须镜像为 (360 - stop) % 360 与 (360 - start) % 360（sprint_to_openscad.py）。
- 2026-09-02: Win10/11 下从插件返回后 Sprint-Layout 因输入法(TSF)锁死是 Sprint-Layout 自身阻塞机制的缺陷，代码无解；官方 workaround 是启动插件前切英文键盘（README 第3.8条）。

- 2026-09-13: **MCP 回写 replace 必须以"原板解析成功"为前提（已修复）**——ensureMcpBoardLoaded 原来解析输入文件失败仅 print（打包后不可见）然后用空板继续；整板(/A)启动 + LLM 添加过元素后 apply(auto→replace) 会用残缺板图整板替换 Sprint-Layout 原板，唯一防线"payload 为空告警"被"已有新增元素"绕过 = 数据丢失。现在解析失败置 app.mcpParseFailed / server.replaceDisabled：主线程 applyMcpBoard 强制降级 insert_new；getBoardInfo 的 applyMode 改报 insert_new；toolApplyToSprintLayout 对显式 replace 抛 McpToolError。三层守卫缺一不可，因为 LLM 可能不查 applyMode 直接传 replace。
- 2026-09-13: **insert_new 增量判同必须用 multiset 计数而非集合（已修复）**——mcp_server.getNewElementsSince 原用 set 判同，原位复制的完全相同元素（Sprint-Layout 允许重叠相同元素）会被当作原有元素，回写时静默丢失；改为逐串计数抵消。为什么不能换成元素 id 判同：undo/importSes/importTextIo(replace) 整体替换 textIo 引用，所有 id 全变，会把整板误判为新增。回归测试 testGetNewElementsSinceMultiset。

- 2026-09-13: **二维码转换异常必须纳入 try（已修复）**——cmdOkSvg_Cmd 的 textToQrcodeStr 原在 try 块外调用，qrcode 库对超长文本抛 DataOverflowError 直接穿出 Tk 回调，无控制台打包 exe 中用户点击按钮毫无反馈。通用规则：文件名校验（verifyFileName/扩展名，只 showwarning+return）可以留在 try 外，但一切可能抛异常的"生成"调用都要套统一的 except+showwarning。

- 2026-09-13: **pointAfterRotated 的 clockwise 参数按Y向上坐标书写，在内部模型（Y向下）里方向相反**——该函数 clockwise=0 分支的矩阵 [[cos,-sin],[sin,cos]] 在内部 Text-IO 坐标（Y向下）中是**屏幕视觉顺时针**（与焊盘/文本ROTATION顺时针为正一致），尽管函数注释写的是"逆时针"；clockwise=1 分支才是视觉逆时针。几何变换（rotateBy）必须用默认 clockwise=0 分支（sprint_track/polygon/pad/text/circle 各类的 rotateBy 均有同样注释）。验证锚点：点(1,0)绕原点转+90°应到(0,1)（3点钟→6点钟）。相关约定：镜像使旋转角取反(360-θ)且文本字形镜像标志(mirrorH/mirrorV)取反；圆弧start/stop存储是逆时针为正，与焊盘旋转方向相反，整体顺时针旋转θ时弧角度要减θ、水平镜像时按180-θ翻转、垂直镜像时取反（SprintCircle.remapArcAngles）。
